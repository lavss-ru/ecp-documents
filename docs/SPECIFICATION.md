# Назначение документа

Настоящий документ описывает функциональные требования к плагину **ECP Documents**.

Он является основной спецификацией проекта и определяет:

- функциональные возможности;
- пользовательские сценарии;
- требования к интерфейсу;
- требования к данным;
- критерии готовности версии 1.0.

При возникновении противоречий между кодом и данным документом приоритет имеет актуальная спецификация после её утверждения.

---

# Назначение плагина

Плагин предназначен для публикации документов, подписанных электронной подписью (ЭЦП), на сайтах WordPress.

Плагин должен позволять пользователю быстро добавить документ в запись или страницу без ручного написания shortcode.

---

# Цели версии 1.0

Версия 1.0 должна обеспечивать:

- выбор PDF из Media Library;
- выбор файла SIG;
- автоматическое формирование shortcode;
- автоматическую вставку shortcode в Classic Editor;
- вывод информации о документе на сайте;
- скачивание PDF;
- скачивание файла SIG;
- отображение признака электронной подписи.

---

# Пользовательские роли

## Администратор

Может:

- добавлять документы;
- выбирать PDF;
- выбирать SIG;
- вставлять shortcode;
- изменять содержимое записей и страниц.

---

## Посетитель сайта

Может:

- видеть опубликованный документ;
- скачать PDF;
- скачать SIG.

Посетитель не имеет доступа к административной части плагина.

---

# Пользовательский сценарий

## Добавление документа

**Статус:** 🚧 В разработке

Последовательность действий:

1. Пользователь открывает запись или страницу.
2. Нажимает кнопку «Добавить документ с ЭЦП».
3. Открывается окно плагина.
4. Пользователь выбирает PDF.
5. Пользователь выбирает SIG.
6. При необходимости изменяет название документа.
7. Плагин формирует shortcode.
8. Shortcode автоматически вставляется в редактор.
9. Пользователь сохраняет запись.

---

# Требования к выбору PDF

**Статус:** ✅ Частично реализовано

Пользователь должен выбирать PDF только через стандартную WordPress Media Library.

Не допускается:

- загрузка через собственые формы;
- хранение отдельных копий файлов.

---

# Требования к выбору SIG

**Статус:** ✅ Частично реализовано

Файл подписи выбирается аналогично PDF.

Используется стандартная Media Library.

---

# Требования к названию документа

**Статус:** ✅ Частично реализовано

После выбора PDF название документа должно определяться автоматически.

Пользователь может изменить название вручную перед вставкой shortcode.

---

# Требования к shortcode

**Статус:** 🚧 В разработке

Формат:

```text
[ecp_document title="Документ" pdf_id="123" sig_id="456"]
```

Требования:

- использовать attachment_id;
- не использовать URL файлов;
- быть обратно совместимым;
- оставаться стабильным между версиями.

---

# Требования к выводу документа

**Статус:** ⏳ Запланировано

На сайте необходимо вывести:

- название документа;
- признак электронной подписи;
- ссылку на PDF;
- ссылку на SIG.

Пример отображения:

```
📄 Приказ №1

✅ Подписано электронной подписью

PDF
SIG
```

Конкретное оформление определяется CSS.

---

# Требования к данным

Плагин не должен хранить:

- URL файлов;
- абсолютные пути;
- относительные пути.

Используются только:

- attachment_id;
- пользовательское название документа.

---

# Требования к Media Library

Все документы должны храниться исключительно в стандартной медиатеке WordPress.

Плагин не должен:

- копировать файлы;
- перемещать файлы;
- изменять структуру каталогов uploads.

---

# Требования к интерфейсу администратора

Интерфейс должен быть:

- простым;
- понятным;
- минималистичным;
- соответствующим стилю WordPress.

Количество действий пользователя должно быть минимальным.

---

# Требования к Frontend

Вывод документа должен:

- корректно работать в теме WordPress;
- использовать стандартный HTML;
- не зависеть от конкретной темы оформления.

---

# Совместимость

Плагин должен быть совместим с:

- WordPress;
- PHP, поддерживаемыми WordPress;
- Classic Editor.

Поддержка Gutenberg может быть добавлена в будущих версиях.

---

# Производительность

Плагин не должен:

- выполнять тяжёлые операции при открытии страницы;
- делать лишние SQL-запросы;
- подключать ресурсы там, где они не используются.

---

# Безопасность

Все входные данные должны проходить:

- проверку;
- очистку;
- экранирование при выводе.

Следует использовать стандартные функции WordPress.

---

# Обработка ошибок

Если пользователь:

не выбрал PDF

или

не выбрал SIG,

плагин должен показать понятное сообщение и не вставлять shortcode.

Не допускается создание некорректного shortcode.

---

# Критерии готовности версии 1.0

Версия считается завершённой после реализации следующих функций:

- выбор PDF;
- выбор SIG;
- автоматическое определение названия;
- формирование shortcode;
- вставка shortcode;
- вывод документа;
- вывод ссылки на PDF;
- вывод ссылки на SIG;
- оформление frontend;
- локализация;
- тестирование.

---

# Что не входит в версию 1.0

Следующие возможности не являются обязательными:

- Gutenberg Block;
- Drag & Drop;
- поддержка нескольких подписей;
- пакетная публикация документов;
- статистика скачиваний;
- REST API;
- импорт и экспорт.

Они могут быть реализованы в будущих версиях.
